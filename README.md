# Tailscale Exit Node → Cloudflare WARP

A single container (systemd as PID 1) that acts as a **Tailscale exit node** with all egress through **Cloudflare WARP**, using **split routing**: Tailscale's control/STUN/P2P traffic goes direct (VPS real IP → UDP hole punching, no DERP relay), while exit-node traffic goes through WARP. Includes a kill switch and a watchdog.

WARP credentials are auto-generated by `wgcf` (`register-warp.sh` / `wgcf-init`).

Credit / upstream (ProtonVPN original): https://code.squarecows.com/ric/tailscale-proton-exit-node — this branch adapts that design from ProtonVPN to Cloudflare WARP.

## Requirements

- Ubuntu 22.04/24.04 (or similar), x86_64 / arm64 / armv7.
- **Rootful podman** — the container is `privileged: true` + systemd + `NET_ADMIN`/`SYS_ADMIN`. All commands below use `sudo`.
  - Do not mix rootless and rootful: they use separate storage. If you previously ran this rootless, `sudo` starts from a clean slate (images, volumes, `ts-state`). You will need to re-run step 2 + 3 below.
- No inbound ports required — Tailscale NAT-traverses (hole punching) by default with outbound UDP, falling back to DERP relays. Optionally allow **inbound UDP 41641** in your cloud security list for more reliable direct connections.
- A Tailscale auth key: admin console → Settings → Keys (reusable, or single-use — single-use requires a fresh key on every rebuild).

## How it works

```
Tailscale peers ─► tailscale0 ─► warp0 (WireGuard WARP) ─► Cloudflare ─► Internet
                    │                                      │
                    │ control plane direct                 │ egress = Cloudflare IP
                    │ (fwmark 0x80000, pri 5210-5270)      │
                    └── exit traffic ─► invert rule ────────┘
                        (unmarked → table 51820, pri 6000) → WARP
```

- `wgcf-init` (one-shot) registers a WARP account → `warp/wgcf-profile.conf` + `warp/.env.warp`.
- `wg-config` (systemd oneshot) creates `warp0` from those credentials (`FwMark=51820`, table 51820, `default dev warp0`), **MTU 1280** to match `tailscale0` (a higher WARP MTU drops return-path packets).
- `kill-switch` installs prohibit routes (metric 900) — traffic is blocked if WARP drops; LAN (`10/8`, `172.16/12`, `192.168/16`), link-local (`169.254/16`) and Tailscale CGNAT (`100.64/10`) stay reachable.
- `tailscaled` + `ts-configure` → `tailscale up --advertise-exit-node`, iptables NAT for exit traffic.
- `vpn-watchdog` (every 30s, threshold 180s) restarts `wg-config` if the handshake goes stale or routing is lost.

## Files

| File | Purpose |
|---|---|
| `docker-compose.yml` | `wgcf-init` (one-shot) + `tailscale-warp` (the whole node) |
| `register-warp.sh` | Downloads/verifies `wgcf`, registers account, writes `warp/.env.warp` |
| `Dockerfile` | systemd image with tailscale + wireguard-tools + iptables |
| `systemd/` | wg-config / kill-switch / ts-configure / vpn-watchdog units + scripts |
| `healthcheck.sh` | Container health (handshake age + tailscale up) |
| `env.example` | Template for `.env` (see Configuration) |

Never commit `.env` or `warp/` (keys + identity — regenerable via step 2).

## Setup

All commands run from the repo root. Use `sudo` everywhere. If your host has the compose plugin, `sudo podman compose ...` works; on hosts with only the standalone binary, substitute `sudo podman-compose ...` (same arguments).

```bash
# 0. Host prep
sudo apt-get update && sudo apt-get install -y podman podman-compose
(sudo podman compose version || sudo podman-compose version)  # sanity check

# /dev/net/tun must exist (it does on stock Ubuntu — verify first)
ls -l /dev/net/tun
# Only if the line above says "No such file": load tun and create the node
if [ ! -c /dev/net/tun ]; then
  sudo modprobe tun || true
  sudo mkdir -p /dev/net
  sudo mknod /dev/net/tun c 10 200
  sudo chmod 600 /dev/net/tun
fi

# IP forwarding for the exit node (host side)
echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/99-tailscale.conf
echo 'net.ipv6.conf.all.forwarding=1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl --system
```

```bash
# 1. Configure (creates .env, keeps it private)
cp env.example .env
chmod 600 .env
nano .env    # set TS_AUTHKEY, check TS_HOSTNAME
grep -E '^TS_AUTHKEY=.+' .env  # must print a non-empty key, no quotes/spaces
```

```bash
# 2. Register WARP — ONCE (re-run only to rotate identity or re-resolve endpoint)
sudo podman compose up wgcf-init
ls -l warp/wgcf-profile.conf warp/.env.warp  # both must exist
chmod 600 warp/.env.warp
```

```bash
# 3. Build + start
sudo podman compose up -d --build
sudo podman compose ps
sudo podman compose logs --tail=100 tailscale-warp
```

Expected boot sequence in the logs: `wg-config` ("warp0 up") → `kill-switch` ("Kill switch active") → `tailscaled` → `ts-configure` ("Tailscale exit node is live").

## Approve + verify

```bash
# One time in the admin console:
# Machines → <TS_HOSTNAME> (default tailscale-warp) → Edit route settings → Use as exit node → Save

# From inside the node (host-side exec, no need to enter the container):
sudo podman exec tailscale-warp-exit tailscale status
sudo podman exec tailscale-warp-exit wg show warp0 latest-handshakes
sudo podman exec tailscale-warp-exit ip rule show
sudo podman exec tailscale-warp-exit ip route show table 51820
```

What good looks like:

- `wg show warp0 latest-handshakes` shows a timestamp within the last ~3 minutes.
- `ip rule show` contains a `priority 6000` invert rule (`not from all fwmark 0xca6c lookup 51820`).
- `ip route show table 51820` contains `default dev warp0 metric 500` plus `prohibit` routes (metric 900, kill switch).

Egress + peer check (on a Tailscale client routing through the node):

```bash
tailscale set --exit-node=tailscale-warp
tailscale ping tailscale-warp             # want "direct", not "via DERP"
curl -s https://cloudflare.com/cdn-cgi/trace | grep warp   # want warp=on
curl -s https://cloudflare.com/cdn-cgi/trace | grep '^ip='  # Cloudflare egress IP
```

## Configuration (`.env`)

| Variable | Required | Default | Description |
|---|---|---|---|
| `TS_AUTHKEY` | Yes | | Tailscale auth key (Settings → Keys) |
| `TS_HOSTNAME` | No | `tailscale-warp` | Machine name in Tailscale |
| `TS_EXTRA_ARGS` | No | `--accept-dns=false` | Extra `tailscale up` flags |
| `KILL_SWITCH` | No | `true` | Block all traffic if WARP drops |
| `WATCHDOG_HANDSHAKE_MAX_AGE` | No | `180` | Stale-handshake threshold (s) before tunnel recycle |

Optional compose-level (not in `.env` by default): `WGCF_VERSION` (default `latest`, e.g. `WGCF_VERSION=v2.2.33` for a pinned, reproducible `wgcf` binary).

WARP values come from `warp/.env.warp` (auto-generated) — no manual WARP config.

## Operating

```bash
# Logs: two places (don't confuse them)
sudo podman compose logs --tail=200 tailscale-warp          # host side, container stdout
sudo podman exec tailscale-warp-exit journalctl -b -u wg-config -u kill-switch -u ts-configure  # inside, systemd units
sudo podman exec tailscale-warp-exit journalctl -u vpn-watchdog.service -n 30

# Status
sudo podman compose ps
sudo podman stats tailscale-warp-exit
sudo podman exec tailscale-warp-exit systemctl status tailscaled wg-config kill-switch ts-configure vpn-watchdog.timer --no-pager

# Recreate after config change
sudo podman compose up -d --build
# Full reset (also wipes ts-state → needs a fresh auth key if yours was single-use)
sudo podman compose down
sudo podman compose up -d --build
```

Inside-container checks (prefix every command with `sudo podman exec tailscale-warp-exit`):

```bash
tailscale status                 # peers + exit-node offer
tailscale netcheck                # want UDP:true + your VPS real IP (not a Cloudflare IP)
tailscale ping <peer>             # direct vs DERP
wg show warp0                     # handshake age + transfer
ip -br link show tailscale0
ip -br link show warp0            # both MTU 1280
ip rule show                      # priority 6000 invert rule present
ip route show table 51820         # default dev warp0 + prohibit routes
ip route show table 51820 | grep prohibit   # kill switch installed?
curl -s https://cloudflare.com/cdn-cgi/trace | grep warp
```

## Debugging

- **`warp=off` / stale endpoint** → Cloudflare rotates endpoint IPs. Re-resolve, then restart the node:
  `sudo podman compose up wgcf-init`, then `sudo podman compose restart tailscale-warp`.
- **No WireGuard handshake** (`wg show warp0` empty / `0`) → `warp/.env.warp` missing (you skipped step 2) or endpoint unreachable. Check `journalctl -u wg-config -n 50` inside the container.
- **`tailscale ping` says `via DERP`** → no direct path (still works, just relayed and slower). `tailscale netcheck` must show `UDP:true` + your VPS real IP. If it shows a Cloudflare IP, exit traffic is leaking into the control path (shouldn't happen in this design). If it stays on DERP and you want direct, optionally allow **inbound UDP 41641** in your cloud security list — usually unnecessary since stateful firewalls already allow the return path.
- **Throughput cap + high CPU** → (1) MTU mismatch — both interfaces must be 1280; (2) CPU ceiling — `tailscaled` userspace WireGuard is CPU-bound, ~15–30 Mbps per core on small shared instances is normal.
- **`container name already in use` on re-up** → older `podman-compose` can't replace in place. Run `sudo podman compose down` before `up -d --build`.
- **`HEALTHCHECK` not shown in `podman ps`** → cosmetic. Podman runs the Dockerfile `HEALTHCHECK` but doesn't render `healthy` like Docker. Self-healing is done by the in-container watchdog; check with `sudo podman healthcheck run tailscale-warp-exit`.
- **Boot log shows `wg-config` erroring on missing vars** → `warp/.env.warp` absent; re-run step 2.
- **Everything worked rootless but broke under `sudo` (or vice versa)** → expected: separate storage. Stick to `sudo` (rootful) for this stack and redo steps 2–3 once.

## Rotate WARP identity

```bash
sudo podman compose up wgcf-init           # re-resolve endpoint + rotate identity
sudo podman compose restart tailscale-warp
```
