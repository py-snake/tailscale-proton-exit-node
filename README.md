# Tailscale Exit Node → Cloudflare WARP

A single container (systemd as PID 1) that acts as a **Tailscale exit node** with all egress through **Cloudflare WARP**, using **split routing**: Tailscale's control/STUN/P2P traffic goes direct (VPS real IP → UDP hole punching, no DERP relay), while exit-node traffic goes through WARP. Includes a kill switch and a 30s watchdog.

WARP credentials are auto-generated by `wgcf` (`register-warp.sh` / `wgcf-init`). Adapted from [ric_harvey/tailscale-proton-exit-node](https://codeberg.org/ric_harvey/tailscale-proton-exit-node).

## How it works

```
Tailscale peers ─► tailscale0 ─► warp0 (WireGuard WARP) ─► Cloudflare ─► Internet
                    │                                      │
                    │ control plane direct                 │ egress = Cloudflare IP
                    │ (fwmark 0x80000, pri 5210-5270)      │
                    └── exit traffic ─► invert rule ────────┘
                        (unmarked → table 51820, pri 6000) → WARP
```

- `wgcf-init` (one-shot) registers a WARP account → `warp/.env.warp`.
- `wg-config` (systemd oneshot) creates `warp0` from those credentials (`FwMark=51820`, table 51820, `default dev warp0`), **MTU 1280** to match `tailscale0` (a higher WARP MTU drops return-path packets → asymmetric loss).
- `kill-switch` installs prohibit routes (metric 900) — traffic blocked if WARP drops; LAN/Tailscale CGNAT stay reachable.
- `tailscaled` + `ts-configure` → `tailscale up --advertise-exit-node`, iptables NAT for exit traffic.
- `vpn-watchdog` (30s) recycles `warp0` if the handshake goes stale or routing is lost.

## Files

| File | Purpose |
|---|---|
| `docker-compose.yml` | `wgcf-init` (one-shot) + `tailscale-warp` (the whole node) |
| `register-warp.sh` | Downloads/verifies `wgcf`, registers account, writes `warp/.env.warp` |
| `Dockerfile` | systemd image with tailscale + wireguard-tools + iptables |
| `systemd/` | wg-config / kill-switch / ts-configure / vpn-watchdog units + scripts |
| `healthcheck.sh` | Container health (handshake age + tailscale up) |
| `env.example` | → `.env`: `TS_AUTHKEY`, `TS_HOSTNAME`, `TS_EXTRA_ARGS`, `KILL_SWITCH`, `WATCHDOG_HANDSHAKE_MAX_AGE` |

## Initial setup

```bash
# 0. Host prep (ROOTFUL podman — the container is privileged + systemd)
sudo apt-get update && sudo apt-get install -y podman
pipx install podman-compose        # or: sudo apt-get install -y podman-compose
sudo mkdir -p /dev/net && [ -c /dev/net/tun ] || sudo mknod /dev/net/tun c 10 200
echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/99-tailscale.conf
sudo sysctl --system

# 1. Configure
cp env.example .env
nano .env    # set TS_AUTHKEY (admin console → Settings → Keys)

# 2. Register WARP — ONCE (or to rotate identity)
podman compose up wgcf-init
ls -l warp/wgcf-profile.conf warp/.env.warp

# 3. Build + start
podman compose up -d --build
podman compose logs -f tailscale-warp
```

Expected boot sequence: `wg-config` ("warp0 up") → `kill-switch` ("Kill switch active") → `tailscaled` → `ts-configure` ("Tailscale exit node is live", `warp=on`).

## Approve + use

```bash
# Admin console → Machines → <TS_HOSTNAME> → Edit route settings → Use as exit node → Save

# On a client:
tailscale set --exit-node=tailscale-warp
tailscale ping tailscale-warp             # "direct ..." (not "via DERP")
curl -s https://cloudflare.com/cdn-cgi/trace | grep -E 'warp|ip='   # warp=on
```

## Configuration (`.env`)

| Variable | Required | Default | Description |
|---|---|---|---|
| `TS_AUTHKEY` | Yes | | Tailscale auth key |
| `TS_HOSTNAME` | No | `tailscale-warp` | Machine name in Tailscale |
| `TS_EXTRA_ARGS` | No | `--accept-dns=false` | Extra `tailscale up` flags |
| `KILL_SWITCH` | No | `true` | Block all traffic if WARP drops |
| `WATCHDOG_HANDSHAKE_MAX_AGE` | No | `180` | Stale-handshake threshold (s) before tunnel recycle |

WARP values come from `warp/.env.warp` (auto-generated) — no manual WARP config.

## Commands inside the container

`podman compose exec tailscale-warp <cmd>` (or `podman exec tailscale-warp-exit <cmd>`).

| Goal | Command |
|---|---|
| Tailscale status / peer connections | `tailscale status` |
| Tailscale network check (UDP, your real IP) | `tailscale netcheck` |
| Ping a peer (direct vs DERP) | `tailscale ping <peer>` |
| WARP tunnel state (handshake age, transfer) | `wg show warp0` |
| Interface MTUs (both should be 1280) | `ip link show tailscale0 && ip link show warp0` |
| Routing policy (pri 6000 invert rule present) | `ip rule show` |
| Exit-node routes + kill-switch prohibits | `ip route show table 51820` |
| Egress proof | `curl -s https://cloudflare.com/cdn-cgi/trace \| grep -E 'warp\|ip='` |
| Service boot log | `journalctl -b -u wg-config -u kill-switch -u ts-configure` |
| Watchdog activity | `journalctl -u vpn-watchdog.service -n 30` |
| All unit states | `systemctl status tailscaled wg-config kill-switch ts-configure vpn-watchdog.timer` |
| Kill switch enabled? | `ip route show table 51820 \| grep prohibit` |

Host-side: `podman compose logs -f tailscale-warp`, `podman compose ps`, `podman stats tailscale-warp-exit`.

## Debugging

- **`warp=off` / stale endpoint** → Cloudflare rotates endpoint IPs. `podman compose up wgcf-init` (re-resolves), then `podman compose restart tailscale-warp`.
- **No WireGuard handshake** (`wg show warp0` empty/0) → check `journalctl -u wg-config -n 50`; verify `warp/.env.warp` exists (run `podman compose up wgcf-init` once) and the endpoint in it is reachable.
- **`tailscale ping` says `via DERP`** → direct connection not established. `tailscale netcheck` should show UDP:true + your VPS's real IP. If it shows a Cloudflare IP, the control path is wrong (shouldn't happen in this design). If it shows your real IP but still DERP, your **cloud security list must allow inbound UDP 41641** (the hole-punch return path; provider-level, not a host port).
- **Throughput cap + high CPU** → two causes: (1) MTU mismatch — confirm both interfaces are 1280 (`ip link show tailscale0 warp0`); (2) CPU ceiling — tailscaled's userspace Go WireGuard is CPU-bound; on a 1-OCPU/shared Oracle instance ~15-30 Mbps is the honest limit (`lscpu`, `nproc`). Kernel-mode tailscaled is already the most efficient option.
- **`podman ps` doesn't show healthy** → Podman builds in OCI format and ignores the Dockerfile `HEALTHCHECK`. Cosmetic; self-healing is done by the in-container watchdog. Optionally `podman build --format docker`.
- **`container name already in use` on re-up** → podman-compose 1.0.x has no `--replace`; run `podman compose down` before `up` (or `up -d --build` won't recreate).
- **wgcf-init re-runs on every `up -d`** → podman-compose 1.0.x ignores `profiles`; harmless (it reuses `warp/wgcf-account.toml` and rewrites `warp/.env.warp`).
- **Rootless podman fails** (privileged/systemd, `NET_ADMIN`) → use rootful (`sudo podman compose ...`).
- **Boot log shows `wg-config` erroring on missing vars** → `warp/.env.warp` absent; you skipped step 2.

## Rotate WARP identity

```bash
podman compose up wgcf-init           # re-resolve endpoint + rotate identity
podman compose restart tailscale-warp
```
